## Upgrade behavior

On first opening a schema-v2 vault with this version, the app rescans existing titles, messages, memories and briefs using the current sensitivity rules. Old restrictions are retained. Existing note and brief approvals are cleared once so their owners review them through the new saved-version flow. Raw conversations, notes, briefs, source links and passwords are preserved. Successful migration advances schema version to 3. Subsequent unlocks preserve fresh approvals unless updated detection finds new restrictions, in which case approvals return to draft for review. A synthetic encrypted-vault regression checks migration and repeated unlock behavior.

## Evening review at d2cc79b — 2026-11-20

Read the [full evening review](https://pre-drink-full-review-nov-20-evening-zzo6.pages.grok.bot/) and compared its central claims with the current source. This is a triage record, not implementation or an independent penetration test.

- **Owner conflict hold: confirmed code defect, first priority.** Owner edits and curator writes share the same `conflict` input; a later agent write can overwrite it and reach automatic publication. Introduce an independent owner-controlled hold, preserve it through agent revisions/undo, and test release and migration boundaries. Only an explicit owner action may clear that hold. Do this before expanding automatic publication.
- **Agent interruption: confirmed product mismatch.** The 15-minute timer tracks owner activity in the app; authenticated agent requests do not renew it. An actively working curator can therefore lose access. Design one owner-started agent session with an explicit duration or an until-Mac-lock option, visible status and one-click stop. Successful authorized activity can count within that owner-approved session; failed requests and background probes must not create or broaden one. Manual lock, sleep, screen lock and revocation remain authoritative. No timeout or protection was changed during this review.
- **Privacy recheck scope: correct the unverified claim.** `privacy_recheck_plan` already includes `curation_notes` content and session labels, and opening a vault calls that plan through enforcement. Re-evaluating sensitivity immediately before publication is a separate defense-in-depth improvement worth testing. Do not describe drafts as entirely absent from the current recheck.
- **Provider workspace: clarify the contract.** Current enforcement and MCP status explicitly permit revision of the matching provider's contributions. Two credentials bound to the same provider share that workspace. Per-client ownership would be a new policy, not the currently implemented provider boundary.
- **Approval reset and classifier gaps:** investigate targeted revocation, owner-visible notices and balanced false-positive/false-negative regressions. Avoid weakening secret protection simply to increase automatic-release counts.
- **Local verification:** add a reproducible local verification entry point and an explicit local pre-push policy; cloud CI remains manual-only under the owner's zero-extra-cost constraint. Signing remains a later owner-funded distribution decision, not an immediate purchase.

Next implementation order: owner hold regression/fix; deliberate agent-session controls; local verification automation; targeted privacy corrections. Real-export and broader model-quality evidence stay separately gated. Competitor convenience claims in the review have not been independently verified.
