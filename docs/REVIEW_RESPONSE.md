## Upgrade behavior

On first opening a schema-v2 vault with this version, the app rescans existing titles, messages, memories and briefs using the current sensitivity rules. Old restrictions are retained. Existing note and brief approvals are cleared once so their owners review them through the new saved-version flow. Raw conversations, notes, briefs, source links and passwords are preserved. Successful migration advances schema version to 3. Subsequent unlocks preserve fresh approvals unless updated detection finds new restrictions, in which case approvals return to draft for review. A synthetic encrypted-vault regression checks migration and repeated unlock behavior.

## Product suggestions retained for later work

- Per-rule explanations beyond the new individual complete-item recheck. Native preview/application with zero changes passed earlier; the new item-selection workflow needs native verification. No detected-credential override is introduced.
- Broader native verification of conversation/snapshot deletion and previous-vault cleanup; their implementation and automated checks now exist.
- No-overwrite backup publication on exFAT; current hard-link publication supports APFS and fails safely where unsupported.
- Direct brief retrieval over MCP, note/brief FTS, pagination, per-project grants and a 5,000-conversation benchmark.
- Explicit one-way Markdown export for agent instruction files or personal knowledge tools; exported plaintext leaves the encrypted boundary.
- Suggested-memory inbox and superseded decisions, always requiring owner review. No automatic approval or cloud calls.
- Optional biometric unlock and client integration only after a signed-app/Keychain design is verified.
- UI component cleanup and accessibility work.

This patch does not add cloud sync, embeddings, automatic extraction, Claude/Grok import, public hosting or private test data.
