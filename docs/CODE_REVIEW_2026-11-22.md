## Finding 1 — Privacy changes could revive old manual approvals

**Severity:** Medium. **Disposition:** fixed; regression reproduced before the fix. **Rule:** source-privacy transitions must invalidate derived sharing approval and outstanding review snapshots.

**Location:** `src-tauri/src/db.rs:538`, `Vault::mark_private`. The baseline updated only `conversations.private`. Agent-curated sources already had version invalidation, but manually saved memories and their briefs retained approval and saved timestamps.

**Reproduction:** import a fictional conversation, save and approve a source-linked manual memory, approve a brief using that memory, mark the conversation private, then make it non-private. The original code immediately returned the memory and brief to shared retrieval without new review. The new regression failed at the assertion that clearing source privacy must not resurrect the old manual release.

**Impact and limits:** an authorized client could receive previously approved derived content again after the owner made the source non-private. Content remained withheld while the source was private; this was not a foreign-provider read or an encryption bypass. The inconsistency mattered because curated contributions and explicit sensitivity clearance already prevented old releases from silently returning.

**Fix:** make an actual privacy change, source-version updates and invalidation of linked memory/brief approvals one transaction. Advance affected saved timestamps, including drafts, so old review hashes cannot be reused after a private/non-private round trip. Only linked records change; repeating the current privacy flag is a no-op. Existing credentials, encrypted format and schema version remain unchanged. The app reports that linked memories and briefs need fresh approval (`src/App.tsx:379`). This is prospective enforcement, not a blanket approval reset on upgrade; past privacy changes cannot be reconstructed from current flags.

**Verification:** `src-tauri/tests/security.rs:538` covers the reproduced round trip, unrelated approval preservation, no-op stability, stale approved/draft reviews, separate brief reapproval and rejection of a pre-change export even after fresh approvals. `src-tauri/src/privacy_recheck.rs:290` injects a failure after the conversation/brief updates and verifies transaction rollback preserves the original flag, evidence version and approvals, then verifies retry. No owner data is involved.
